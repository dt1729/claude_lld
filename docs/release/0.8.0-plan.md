# 0.8.0 release plan

**Status:** proposed. No version is bumped yet; `plugin.json`, `marketplace.json` and the
README badge still say 0.7.0.

## Version

**0.8.0**, a minor bump.

The CHANGELOG policy: versions are `0.x`, a minor bump *may* break a contract already
written, and each entry says which ones do. Every release so far has been a minor bump,
breaking or not (0.6.0 added a prerequisite, 0.7.0 required a new contract section). This
one adds a skill, which changes what loads into a user's sessions, so it is a minor bump
rather than a patch. A patch (0.7.1) would be defensible only if the release is docs alone
and the `workflow` skill is held back.

## Scope

### Committed

- **Docs rewrite.** `docs/guide/` (getting-started, workflow, troubleshooting) and
  `docs/reference/` (gate, rules, contracts, commands, skills, sweep, detectors,
  enforcement), each enumerated from `scripts/` rather than from earlier prose. README
  reduced to the front door: pitch, install, the two loops, a feature table linking into
  the reference.
- **`workflow` skill** (`skills/workflow/SKILL.md`). Routes the model to the right loop and
  step, states what done means, and lists the diagnose-side direction as not built so it is
  never described as a feature.

## Breaking changes

**None expected.** A contract that validates under 0.7.0 validates under 0.8.0: no script
that reads a contract, a waiver row or a hook payload changes in the committed scope. The
new skill adds guidance; it removes none.

Two optional items could break things, and the CHANGELOG must say so if they ship that way:

- the "shape collision" rename, if it renames `--json` keys (`duplication_rate`) that
  someone parses;
- withholding the dead figure, if `dead` disappears from `--json` instead of being flagged
  unconfirmed.

## Risks

- **The docs describe the code at one commit.** Each reference page enumerates rules, flags
  and exit codes. A script change that does not touch the page makes it wrong, and nothing
  checks it. Mitigation worth considering: a test that the rule numbers in `rules.md` match
  the ones the detectors can emit.
- **The `workflow` skill may fire too often.** Its description triggers on "where to start"
  and "what next", which are common phrasings. If it loads in sessions that do not use
  lld-seed it spends context; narrow the description if that shows up.
- **The skill and the guide can drift.** `skills/workflow/SKILL.md` and
  `docs/guide/workflow.md` say the same thing twice, which is the duplication incident 008
  warns about. The skill links to the guide; keep the step tables in one place if they
  start to diverge.
- **The test count drifts.** It is in the badge, the Status section and this plan, and was
  already wrong once (the README said 254 while the badge said 265, against 356 real).
- **Optional items under release pressure.** The diagnose-loop items change what the sweep
  reports. Shipping one without its test repeats the 0.7.0 pattern where most of what the
  detector called dead was its own blindness.
- **The gate is still unverified in a live session.** A release that rewrites the docs
  around it does not change that; the checklist item above is the cheapest way to close it.
